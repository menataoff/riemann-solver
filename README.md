# Практика к §15: точный решатель задачи Римана

Этот репозиторий содержит **часть 1.1 и пункты 1–6 части 1.2** задания из [`docs/prac15.pdf`](docs/prac15.pdf). Программа решает одномерную задачу о распаде начального разрыва для совершенного газа, вычисляет параметры между волнами, типы и скорости волн, состояние на выбранном луче и поток через неподвижную грань. Численная схема на сетке, пять автоматических тестов Торо, графики и отчёт относятся к следующим этапам работы.

Теоретические формулы здесь взяты только из [§15 лекции курса](https://polinakozhurina.github.io/cfd-course/sem1/s1-15.html). Табличные значения тестов для ручной сверки приведены в самом задании.

## Сборка и запуск

Нужны компилятор C++17 и CMake версии не ниже 3.16. Внешних библиотек для расчётного кода нет. Проверено с GCC 13.3 и CMake 3.28.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/prac15 config.yaml
```

Если программа запускается из корня проекта, имя файла можно опустить: `./build/prac15`. Для другой задачи скопируйте `config.yaml`, измените параметры и передайте путь к копии. Программа возвращает код `0` при обычном решении и при корректно обнаруженном вакууме; при ошибке входных данных или вычислений — код `1`, а сообщение пишет в `stderr`.

`output.destination: console` отправляет диагностический результат в терминал. При `output.destination: file` результат записывается в `output.file`; его родительский каталог создаётся автоматически, файл при новом запуске перезаписывается. Ошибки всегда видны в терминале. Расчётная библиотека ничего не печатает: выбор места вывода делает только `main.cpp`.

## Что задано в `config.yaml`

```yaml
gas:
  gamma: 1.4

method:
  solver: exact
  scheme: none

domain:
  x_min: 0.0
  x_max: 1.0
  discontinuity: 0.5

initial:
  left:
    rho: 1.0
    u: 0.0
    p: 1.0
  right:
    rho: 0.125
    u: 0.0
    p: 0.1

boundary:
  left:
    type: transmissive
  right:
    type: transmissive

output:
  destination: console
  file: output/run.log
  sample_x: 0.5
  sample_time: 0.25
```

| Ключ | Смысл | Ограничение |
| --- | --- | --- |
| `gas.gamma` | показатель адиабаты совершенного газа | больше 1 |
| `method.solver` | имя решателя задачи Римана | сейчас только `exact` |
| `method.scheme` | имя схемы на сетке | сейчас только `none` |
| `domain.x_min`, `domain.x_max` | границы отрезка, на котором позже строятся профили | `x_min < x_max` |
| `domain.discontinuity` | положение исходного разрыва (x_0) | строго внутри отрезка |
| `initial.left`, `initial.right` | постоянные состояния слева и справа от (x_0) | каждый блок содержит `rho`, `u`, `p` |
| `rho`, `u`, `p` | плотность, скорость, давление | `rho > 0`, `p > 0`; скорость любого знака |
| `boundary.left`, `boundary.right` | будущие граничные условия для схемы на сетке | `type: transmissive` или `type: fixed` |
| `output.destination` | место диагностического вывода | `console` или `file` |
| `output.file` | путь к текстовому файлу при `destination: file` | обязательный непустой путь |
| `output.sample_x` | точка для отбора решения | внутри отрезка, включая границы |
| `output.sample_time` | момент отбора решения | больше 0 |

В `initial` записываются **начальные условия** задачи Римана: (W_L=(\rho_L,u_L,p_L)) при (x<x_0) и (W_R=(\rho_R,u_R,p_R)) при (x>x_0). В §15.2 скорость звука (a=\sqrt{\gamma p/\rho}), удельная внутренняя энергия (e=p/[\rho(\gamma-1)]). Ровно на исходном разрыве значение не задаётся: решение при (t>0) определяется отбором по лучу.

`boundary` хранит **граничные условия будущего расчёта на сетке**. `transmissive` означает копирование состояния из ближайшей внутренней ячейки в фиктивную. Для фиксированного состояния пишите, например:

```yaml
boundary:
  left:
    type: fixed
    rho: 1.0
    u: 0.0
    p: 1.0
  right:
    type: transmissive
```

Текущий решатель получает только два состояния по сторонам *одного* разрыва и не использует `boundary` или размер области при вычислении (p_*,u_*). Границы понадобятся, когда будет реализована схема на сетке. `sample_x`, `sample_time` и `discontinuity` определяют единственное число (S=(x-x_0)/t), передаваемое функции отбора. Для потока через неподвижную грань всегда используется (S=0).

Парсер поддерживает подмножество YAML, достаточное для показанного файла: вложенные отображения, скалярные значения, отступы по два пробела и комментарии `#`. Списки, YAML-ссылки, кавычки и многострочные значения не поддерживаются. Все показанные ключи обязательны; неизвестные имена и дубли ключей вызывают ошибку. Так опечатка в параметре не приводит к молчаливому использованию неверного значения.

Подробный разбор конфигурации находится в [`docs/01_config.md`](docs/01_config.md).

## Алгоритм решения

### 1. Давление между волнами

Сначала для каждой стороны используется функция волны (f_K(p)) из (15.10) и (15.11). При (p>p_K) выбирается ударная ветвь; при (p\le p_K) — ветвь разрежения. Давление (p_*) является положительным корнем уравнения (15.13):

\[
f_L(p_*)+f_R(p_*)+u_R-u_L=0.
\]

Начальное приближение выбирается по правилу GUESSP из §15.8. Если давления различаются не более чем вдвое и акустическая оценка (15.18) лежит между ними, используется она (`acoustic`). Если акустическая оценка меньше обоих давлений, используется формула двух волн разрежения (15.19), `two_rarefactions`. В остальных случаях используется формула двух ударных волн (15.20), `two_shocks`. Далее выполняются итерации Ньютона (15.16) с производными (15.17).

Остановка наступает при относительном изменении давления меньше `1e-6`. Число итераций выводится. Если шаг Ньютона дал неположительное число, берётся половина предыдущего положительного давления. Фиксированного нижнего порога нет, чтобы не исказить решение рядом с вакуумом; если положительное число уже невозможно представить в `double`, выдаётся ошибка. После 100 итераций без сходимости тоже выдаётся ошибка. Функция `solve_pressure` возвращает и найденное давление, и начальную оценку, и метод её выбора, и число итераций. См. [`docs/02_pressure.md`](docs/02_pressure.md).

### 2. Скорость и плотности около контактного разрыва

Скорость (u_*) находится по (15.14). Давление и скорость на двух сторонах контакта одинаковы, плотности (\rho_{*L}) и (\rho_{*R}) могут различаться (§15.4). Для каждой стороны плотность вычисляется по ударной адиабате из §15.5 или по формуле разрежения (15.11), исходя из сравнения (p_*) и (p_K). Результат хранится в `StarState`. См. [`docs/03_star_state.md`](docs/03_star_state.md).

### 3. Типы волн и их скорости

`calculate_wave_speeds` сравнивает (p_*) с начальным давлением каждой стороны. Для ударной волны возвращается одна скорость фронта. Для веера разрежения возвращаются две скорости: головы и хвоста. Формулы — (15.21) и правые аналоги из §15.9. Результат хранится в `WavePair`. См. [`docs/04_wave_speeds.md`](docs/04_wave_speeds.md).

### 4. Отбор решения

`sample_solution(S, ...)` выбирает состояние на луче (S=(x-x_0)/t). Сначала определяется сторона контактного разрыва сравнением с (u_*), затем по скоростям волн выбирается исходное состояние, состояние около контакта или состояние внутри веера. Внутри веера используются формулы (15.22) и правый аналог из §15.9. Ровно на контакте функция выбирает левый предел; давление и скорость там совпадают, а плотность имеет два предельных значения. См. [`docs/05_sampling.md`](docs/05_sampling.md).

### 5. Поток на грани

`calculate_face_flux` вызывает отбор при (S=0) и считает три компоненты потока по (15.23):

\[
F_m=\rho u,\qquad F_{imp}=\rho u^2+p,\qquad
F_e=(\rho E+p)u,\quad \rho E=\frac{p}{\gamma-1}+\frac{\rho u^2}{2}.
\]

Возвращаются и состояние на грани, и поток. Это готовый интерфейс для будущего шага схемы Годунова; сам шаг по сетке пока отсутствует. См. [`docs/06_face_flux.md`](docs/06_face_flux.md).

### 6. Проверка вакуума

До итераций Ньютона `check_vacuum` проверяет условие (15.15): положительный корень существует, если (u_R-u_L<2(a_L+a_R)/(\gamma-1)). При нарушении условия `solve_riemann` возвращает результат с `vacuum.occurs = true` и без численного решения. Программа выводит оба числа и штатно заканчивает работу; `NaN` и попытки вычислить поток не возникает. Строить решение с вакуумом в этой работе не требуется. См. [`docs/07_vacuum.md`](docs/07_vacuum.md).

## Структура и использование библиотеки

```text
include/                   объявления типов и функций
  state.hpp                примитивное состояние, консервативное состояние, поток
  wave_function.hpp        скорость звука, функция волны и её производная
  pressure_solver.hpp      GUESSP и Ньютон для p_star
  star_state.hpp           u_star и две плотности
  wave_speeds.hpp          типы и скорости волн
  sample_solution.hpp      отбор W(S)
  face_flux.hpp            W(0) и поток через неподвижную грань
  vacuum.hpp               проверка условия (15.15)
  exact_riemann_solver.hpp сборка полного результата
  riemann_flux_solver.hpp  общий интерфейс потока для будущих решателей
  exact_flux_solver.hpp    точный решатель через общий интерфейс
  solver_factory.hpp       создание решателя по имени
  config.hpp, output.hpp   конфигурация и диагностический вывод
src/                       реализации соответствующих .hpp
main.cpp                   чтение файла, вызовы, форматирование вывода
config.yaml                пример входного файла
docs/01_config.md          пояснение входных условий
docs/02_pressure.md ...    пояснения к пунктам 1–6 части 1.2
docs/prac15.pdf            текст задания
```

CMake собирает `prac15_riemann` как статическую библиотеку. Её код зависит только от типов состояний и числовых параметров. `prac15_config` отдельно читает YAML и управляет выводом. Исполняемая программа `prac15` соединяет эти части. В другом проекте можно подключить `include/` и линковать `prac15_riemann`, не используя `config.yaml`.

Пример вызова из C++:

```cpp
#include "exact_riemann_solver.hpp"
#include "sample_solution.hpp"
#include "face_flux.hpp"

PrimitiveState left{1.0, 0.0, 1.0};
PrimitiveState right{0.125, 0.0, 0.1};
RiemannResult result = solve_riemann(left, right, 1.4);
if (!result.vacuum.occurs) {
    const RiemannSolution& solution = *result.solution;
    PrimitiveState at_face = sample_solution(0.0, left, right, 1.4,
                                             solution.star, solution.waves);
    FaceResult face = calculate_face_flux(left, right, 1.4,
                                          solution.star, solution.waves);
}
```

Для будущей схемы предусмотрен `RiemannFluxSolver` с методом `solve_flux(left, right, gamma)`. `ExactFluxSolver` уже реализует этот интерфейс. `make_solver("exact")` создаёт его по имени из файла конфигурации. Новый решатель, например HLL, можно будет добавить отдельным классом, реализующим тот же метод, и новой ветвью в фабрике; код схемы, вызывающий интерфейс, останется прежним. Точная функция `solve_riemann` отдельно сохраняет все промежуточные величины, необходимые для отчёта и графиков. Сейчас доступны только `exact` и `none` соответственно: другие имена отклоняются явно.

Зависимости расчётных частей направлены в одну сторону: `wave_function` используется в расчёте давления и скоростей; результаты давления нужны для `star_state`, затем для `wave_speeds`, `sample_solution` и `face_flux`. `exact_riemann_solver` собирает первые три результата после проверки вакуума. Все функции получают данные через аргументы, не хранят изменяемого глобального состояния и не обращаются к сетке. Поэтому в будущем их можно вызывать независимо на разных гранях, в том числе из параллельного цикла. Сетку, граничные условия, обмен фиктивными ячейками, шаг по времени и ввод-вывод можно добавить отдельными модулями без изменения формул точного решателя.

## Текущие ограничения

- Решение с вакуумом не строится, поскольку задание требует только обнаружить его.
- Граничные условия из `config.yaml` пока проверяются и сохраняются, но не применяются: схема на сетке ещё не реализована.
- Программа выводит один выбранный луч и поток при (S=0). Файлы профилей и графики не относятся к пунктам 1.1–1.2.
- Автоматические тесты, таблицы отклонений для пяти тестов Торо, PDF-отчёт и проект комплекса по всем вопросам 2.1–2.10 ещё предстоит выполнить по следующим указаниям.
